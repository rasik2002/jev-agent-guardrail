# Requirements: Jev Agent Guardrail

## Introduction

LLM agents with real tools occasionally propose actions that are destructive, off-intent, or leak data. This feature adds a fast decision endpoint that scores each proposed tool call with Jev and returns a verdict the agent must respect before executing.

## Requirements

### Requirement 1: Score a proposed tool call

**User Story:** As an agent developer, I want to POST a proposed tool call and get a verdict, so that my agent can branch before executing.

#### Acceptance Criteria
1. WHEN a client POSTs `{user_request, tool, arguments}` to `/guard` THEN the system SHALL return HTTP 200 with `verdict` in `{allow, ask, block}`.
2. WHEN the body is not JSON or is missing `user_request`, `tool`, or `arguments` THEN the system SHALL return HTTP 400 with an `error` field.
3. WHEN the verdict is computed THEN the response SHALL include `risk` (0..2), `intent_match` (0..1), `exfiltration` (0..1), `reasons` (list of strings), `jev_model`, `jev_cost_usd`, `latency_ms`, and `decision_id`.

### Requirement 2: Typed questions, not prose

**User Story:** As a security-minded developer, I want the judgement to come from typed probabilities, so that there is no free text to parse or inject.

#### Acceptance Criteria
1. WHEN the system calls Jev THEN it SHALL send exactly three questions: `risk` (score, 3 criteria ordered safest to most dangerous), `intent_match` (noul), `exfiltration` (noul).
2. WHEN building the Jev state THEN the system SHALL include only `user_request`, `proposed_tool_call {tool, arguments}`, and optional `agent_context`. No instructions in state.
3. WHEN the policy produces `reasons` THEN those strings SHALL be generated by policy code from numeric thresholds, never copied from model output.

### Requirement 3: Configurable policy

**User Story:** As an operator, I want to tune thresholds without redeploying code.

#### Acceptance Criteria
1. WHEN environment variables `POLICY_BLOCK_RISK`, `POLICY_ASK_RISK`, `POLICY_BLOCK_INTENT`, `POLICY_ASK_INTENT`, `POLICY_BLOCK_EXFIL` are set THEN the system SHALL use them instead of defaults.
2. WHEN `exfiltration >= POLICY_BLOCK_EXFIL` THEN verdict SHALL be `block` regardless of other answers.
3. WHEN `intent_match < POLICY_BLOCK_INTENT` THEN verdict SHALL be `block`.
4. WHEN `risk >= POLICY_BLOCK_RISK` AND `intent_match < POLICY_ASK_INTENT` THEN verdict SHALL be `block`.
5. WHEN `risk >= POLICY_ASK_RISK` OR `intent_match < POLICY_ASK_INTENT` (and no block rule fired) THEN verdict SHALL be `ask`.
6. Otherwise verdict SHALL be `allow`.

### Requirement 4: Fail closed

**User Story:** As an operator, I want outages to pause the agent, not free it.

#### Acceptance Criteria
1. WHEN Jev returns an error or times out THEN the system SHALL return HTTP 502 with `verdict: ask`.
2. IF the SSM parameter cannot be read THEN the system SHALL return HTTP 502 with `verdict: ask`.

### Requirement 5: Audit log

**User Story:** As an operator, I want every decision recorded so I can replay a session.

#### Acceptance Criteria
1. WHEN a decision is produced THEN the system SHALL write one DynamoDB item keyed by `decision_id` containing the request fields, the decision fields, `session_id`, `created_at`, and `expires_at`.
2. WHEN items are written THEN `expires_at` SHALL be `created_at + LOG_TTL_DAYS * 86400` and the table SHALL have TTL enabled on it.
3. WHEN querying by session THEN a GSI `by-session` (hash `session_id`, range `created_at`) SHALL exist.
4. WHEN writing floats THEN they SHALL be converted to `Decimal`.

### Requirement 6: Secrets and IAM

#### Acceptance Criteria
1. WHEN the Lambda needs the OpenRouter key THEN it SHALL read it from an SSM SecureString parameter, cached per container.
2. WHEN IAM is provisioned THEN the function SHALL have `ssm:GetParameter` on that single parameter ARN and DynamoDB write on the single table only.
3. The key SHALL NOT appear in `template.yaml`, source, or any committed file.

### Requirement 7: Local developer experience

#### Acceptance Criteria
1. WHEN a developer runs `python -m pytest -q` with no network and no AWS credentials THEN all tests SHALL pass.
2. WHEN a developer sets `OPENROUTER_API_KEY` and runs `cli.py` or `examples/agent_demo.py` THEN they SHALL get verdicts without deploying to AWS.
3. WHEN a developer runs `sam validate --lint` THEN the template SHALL pass.
